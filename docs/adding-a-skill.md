# Adding a skill

Inspect the canonical repository and record the exact reviewed commit and `SKILL.md` path. Read the skill scope, repository license, scoped license where present, notices, installation behavior, and likely conflicts. Use a stable internal ID even if the upstream display name changes.

Choose one authority role. Framework and creative authorities are exclusive within a route; specialists and reviewers must be task-scoped. Mark unstable or preview sources as experimental and pin them.

Add behavioral tests that show both intended activation and leakage prevention. Regenerate attribution and run the full check.
