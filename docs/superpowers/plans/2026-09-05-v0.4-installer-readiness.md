# v0.4 Installer and Readiness Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make managed capability dormancy, workflow dependencies, license evidence, and filesystem boundaries visible and verifiable before a host is reported ready.

**Architecture:** Extend versioned registry metadata, apply a deterministic Codex policy overlay during staging, and share non-following filesystem validation between installer and doctor. Preserve current host paths and upgrade behavior while adding readiness dimensions.

**Tech Stack:** Node.js 22 ESM, built-in filesystem/crypto/test modules, JSON and constrained YAML text transforms, no runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-05-v0.4-hardening-workflow-design.md`

## Global Constraints

- Stage and validate every source before mutating either host.
- Preserve unrelated host rules and upstream OpenAI interface/dependency metadata.
- Never follow symlinks, junctions, reparse points, or root escapes.
- Preserve existing doctor fields while adding readiness dimensions.
- Regenerate credits after registry changes.
- Run `npm run check` before reporting completion.
