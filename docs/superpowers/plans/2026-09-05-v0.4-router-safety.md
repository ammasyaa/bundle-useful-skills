# v0.4 Router and CLI Safety Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make explicit routing fail closed for sensitive work, malformed CLI input, missing targets, removed framework authorities, and invalid activation budgets without changing valid command syntax.

**Architecture:** Extract strict command parsing and sensitive-feature classification into small dependency-free modules. Keep `route()` as the compatibility entry point, but make authority, target, and budget validation derive from normalized inputs and registry configuration.

**Tech Stack:** Node.js 22 ESM, built-in test runner, JSON registries, no runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-09-05-v0.4-hardening-workflow-design.md`

## Global Constraints

- Preserve valid `route`, `report`, `detect`, and `triage` commands and existing route fields.
- Keep the runtime dependency-free.
- Add behavior tests before each behavior change.
- Select exactly one required framework authority.
- Never omit a required security gate.
- Run `npm run check` before reporting completion.

```js
export function validateActivationBudget(value) {
  const keys=['targetMin','targetMax','warnAbove','justifyAbove'];
  if (!keys.every(key=>Number.isInteger(value?.[key])&&value[key]>=0)) throw new Error('Invalid activation budget');
  if (!(value.targetMin<=value.targetMax&&value.targetMax<=value.warnAbove&&value.warnAbove<value.justifyAbove)) throw new Error('Invalid activation budget ordering');
  return value;
}
```
