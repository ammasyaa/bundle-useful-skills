# v0.4 Searching, CI, and Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add bounded project-aware skill searching, verify the project on three operating systems, and document the complete user-to-GitHub workflow accurately.

**Architecture:** Build Searching from a safe scanner, pure classifier, and registry matcher. Add it to the existing CLI without replacing explicit routes, then make CI and documentation describe the exact checks and host guarantees.

**Tech Stack:** Node.js 22 ESM, built-in filesystem/test/child-process modules, JSON output, GitHub Actions, Markdown and Mermaid.

**Spec:** `docs/superpowers/specs/2026-09-05-v0.4-hardening-workflow-design.md` and `docs/superpowers/specs/2026-09-05-searching-stage-design.md`

## Global Constraints

- Searching is a pre-routing stage, not a fourth platform.
- Do not read secret values, dependency trees, build output, caches, or paths outside the repository.
- Ambiguous repositories return evidence and `needsInput: true` instead of guessing.
- Preserve explicit route and file-map detect behavior.
- CI permissions remain read-only.
- Documentation must distinguish verified behavior from host limitations.

Assert that selected skills pass normal route validation and that near matches explain platform, framework, target, phase, scope, authority, or conflict rejection.
