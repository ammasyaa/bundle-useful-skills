# Automation routing

Use this lane for agent, workflow, and integration engineering: MCP servers, skills, scheduled and event-driven scenarios, and system-to-system integration. Plan before implementing; these systems fail in production, not in review. Design the unhappy paths first — retries, partial failure, duplicate delivery, rate limits — and make every write idempotent and keyed by a stable source identifier. State that must outlive a run goes in a durable store, never in run context. Separate read capability from write capability, and treat anything with spend, publish, or delete authority as sensitive: it activates the security gate and starts paused or draft by default. Credentials and account identifiers live in the deployment environment, never in the repository.
