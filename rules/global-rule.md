## Development skill bundle routing

For every task, consult the `development-skill-router` skill before substantive work.

- For website, desktop, or mobile development, classify the platform, framework, and current phase. Select the smallest compatible bundle and read each selected skill or bundled reference before using it.
- In the first progress update, write `Skill bundle: development-skill-router -> ...` and list only the capabilities actually being used. Re-route and report again when the task phase changes.
- Before completing work that changed code or configuration, route the verification phase, follow `verification-before-completion` and any security or release gates, and report the evidence.
- In the final answer, write `Skill bundle used: ...`. Do not claim that a capability ran when its instructions were unavailable or unread; report that gap explicitly.
- For a task outside website, desktop, or mobile development, write `Skill bundle: development-skill-router (triage only; no development capability applies)` and continue with the relevant host capabilities.
- Keep the full installed inventory dormant. Never load every skill into context for one task.
